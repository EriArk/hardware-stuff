# OctoFox Library

Личная веб-библиотека: загрузка FB2 и EPUB, поиск, коллекции, чтение, закладки и серверная озвучка. Открывается в браузере на компьютере, планшете и телефоне.

**Ранняя версия для отдельной тестовой установки.** Здесь перенесена работающая библиотека и удалены сборщики внешних каталогов. Мастер Companion и переводы ещё разрабатываются. Пока аккаунты и каталог обслуживает BookLore; его первоначальная настройка выполняется отдельно.

## Установка

Нужны Python 3.12+ для генерации настроек и Docker Engine с Compose v2. Сборка озвучки загружает модели и зависимости, поэтому требует Интернета и нескольких гигабайт свободного места. После сборки голосовой контейнер работает без сети.

Из этой папки:

```sh
python tools/configure.py
docker compose up -d --build
```

Откройте BookLore на `http://localhost:8081`, завершите его начальную настройку, добавьте каталог `/books` и создайте OPDS-аккаунт. Затем откройте `http://localhost:8080` и войдите этим аккаунтом. Учётная запись администратора BookLore и OPDS-аккаунт — разные сущности.

На удалённом хосте административный порт доступен через SSH-туннель:

```sh
ssh -L 8081:127.0.0.1:8081 user@server
```

Для доступа в домашней сети перед первым запуском задайте адрес своего сервера:

```sh
python tools/configure.py --origin http://192.168.1.20:8080 --bind 0.0.0.0
```

Адрес приведён для примера. Открывайте сайт по тому адресу, который указан в `OCTOFOX_ORIGIN`. Генератор не перезаписывает существующий `.env`: сохраняйте его вместе с резервной копией. Для публикации через HTTPS задайте соответствующий origin и обратный прокси. Сам по себе запуск Compose не настраивает внешний доступ или Cloudflare.

## Озвучка

```sh
docker compose --profile speech up -d --build
```

Начальные голоса — русские Piper/Silero. Выбор голоса и скорость доступны в читалке. Модели загружаются из источников разработчиков с проверкой контрольных сумм; в Git они не хранятся. См. [speech/README.md](speech/README.md).

## Данные и обновления

Книги пользователей, состояние чтения, база BookLore и аудиокэш находятся в именованных Docker-томах. Удаление книги из личной полки не стирает её позицию чтения. Перед обновлением остановите **эту** установку и сохраните её тома и `.env`. Команда `docker compose down` сохраняет тома; не используйте `down -v`, если данные нужны.

Не подключайте эту раннюю сборку к каталогам данных другой работающей установки. При замене личного файла книги прогресс сохраняется, но изменённое издание может иметь другой текст в той же позиции.

## Запуск без Docker

Для разработки веб-части достаточно Python 3.12; внешних runtime-зависимостей нет:

```sh
python -m pip install -e .
octofox-library
```

Настройте переменные окружения `OCTOFOX_UPSTREAM` (адрес BookLore с `/api/v1/opds`), `OCTOFOX_ORIGIN`, `OCTOFOX_DB`, `OCTOFOX_BIND`, `OCTOFOX_PORT`. Без подключённого BookLore войти нельзя. `OCTOFOX_SPEECH_SOCKET` включает серверную озвучку через Unix-сокет; без него веб-чтение остаётся доступным.

## Проверки

```sh
python -m pip install -e .
python -m unittest discover -s tests
node --test tests/test_books_web_*.cjs
```

Тесты используют временные данные и синтетические книги. Они не обращаются к личной библиотеке. Проверки реального аудио и поведения мобильного браузера выполняются отдельно.

При установленном Playwright и его Chromium/WebKit можно выполнить проверку адаптивной разметки: `node tools/verify-browser.cjs`. `TEST_WEBKIT=1` выбирает WebKit; `QA_OUTPUT` задаёт папку снимков, по умолчанию `test-results/browser`. Проверка использует локальный HTTP-стенд с вымышленными книгами. Это не проверка физического iPhone.

На Linux контейнерная проверка backend выполняется без внешней сети:

```sh
docker run --rm --network none -e PYTHONPATH=/work/src -v "$PWD:/work:ro" -w /work octofox-library:0.1.0-alpha1 python -m unittest discover -s tests
```

Проверка обоих настоящих голосов после сборки:

```sh
docker run --rm --network none --memory 2g --cpus 1 -v "$PWD/speech/verify.py:/app/verify.py:ro" octofox-speech:0.1.0-alpha1 python /app/verify.py
```
